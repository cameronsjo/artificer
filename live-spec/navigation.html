navigation.

The spine. Four surfaces, four jobs — breadcrumb for location, sidebar for the between-section spine, app bar for global chrome, tabs for switching the view inside one surface. One spine per page: a sidebar or a top nav, never both.

Breadcrumb · where am I

Location in a hierarchy. Links are secondary; the last item is the current page (aria-current="page") and reads at full strength. Separators are .crumb__sep. Promoted v0.10.0 — this exact pattern was copy-pasted into ~14 spec pages.

App bar · global chrome

Brand · optional search · spacer · trailing actions. The wordmark is mono (and a sanctioned .whimsy home). At most one .btn--primary in the bar. The hamburger (.appbar__menu-btn) appears only below 800px to open the drawer — and carries .btn--icon-prominent: a lone primary icon control rests at full --fg, because it has no row of neighbors to borrow prominence from (ghost's --fg-secondary is for icons in a cluster). Apply .wordmark to an inline element inside .appbar__brand, not to the brand container itself — the container is a flex row and a ::after period in flex becomes a separate flex item. display:inline-block on .wordmark guards against this.

Appbar modifiers

.appbar--contained zeroes the bar's built-in inline padding so a surrounding .container owns the gutter — prevents double-inset when the bar lives inside a padded column. .appbar--static opts out of position:sticky for compact tool surfaces or layouts where stickiness conflicts with a second sticky plane (sidenav).

artificer

.appbar--contained + .appbar--static — brand aligns flush with the container column. Combine modifiers freely.

Masthead · document-surface top nav

The document-surface counterpart to .appbar — non-sticky, no border, no chrome. A quiet single-row header for reading surfaces (blog, essays, release notes): brand, a few links, optional meta. It scrolls with the page rather than pinning, and carries no background or border of its own — it belongs to artificer-editorial.css, not the core tool-chrome file. Compose the brand with .wordmark--stop-none for a period-bearing mark, and a theme toggle with .theme-toggle--inline to opt it out of the fixed corner slot. On narrow viewports the brand holds row one; nav and meta wrap below it — no hamburger, that's .appbar's tool territory.

Hierarchy at scale — a long spine

Grouping alone isn't hierarchy: at ~15 uniform rows the group labels recede and the only anchor is the active row. The .sidenav__group header now sticks as the spine scrolls and carries a divider above each section — so you always know which group you're in without reading every row. Scroll this list; the section label pins. No new tokens, and the treatment is inert on short, non-scrolling navs.

SPA section-switch — <button> nav items

A single-page app switches sections without navigating between documents — that's a <button>, not an <a href>. .sidenav button now receives the full treatment: resting, hover, focus, and the [aria-current] accent rail. Collapsed rail — .sidenav--rail

Icon-only, 56px. Labels move to screen-reader-only (kept in the a11y tree, not display:none); counts shrink to a dot. For dense apps where the spine should yield horizontal room.

Tabs · switch the view

Switch which view you're looking at within one surface. Underline marks the active tab. Use role="tablist" + aria-selected for in-page panels, or links + aria-current for routed views.

The behavior ships too. .tabs is the look; artificer-tabs.js is the unavoidable-JS half of the WAI-ARIA tabs pattern — roving tabindex, ←/→ (or ↑/↓ under aria-orientation="vertical"), Home/End, and panel toggling from each tab's aria-controls. Same precedent as ArtificerFocus.trap(): the system ships the a11y JS, not just the CSS.

Tabs vs. segmented — not the same control

They look alike and do different jobs. Tabs switch the view (different content). The segmented control switches a parameter of one view — a time window, a density. If the content stays and only its shape changes, it's segmented (.timerange), not tabs.

Rules

  1. One spine per page. A sidebar or a top nav as the primary spine — never both. Two navs and the page has no center.
  2. Active state uses aria-current="page" (or aria-selected for tabs), not class alone — the accent rail/underline is the visual echo of a real attribute.
  3. Tabs switch the view; segmented switches a parameter. Same shape, different job. Don't reach for .tabs to filter one view.
  4. Nav touch targets are ≥44px. Sidebar links and tabs already are. Dense tables may go smaller; navigation may not.
  5. The drawer traps focus and returns it to the trigger on close; Esc and the scrim both dismiss. Reuse ArtificerFocus.trap().
  6. Breadcrumb links are secondary; only the current page is full-strength. The crumb states location — it isn't the primary way to move.
  7. Collapse to a rail, not to nothing. When space is tight, .sidenav--rail keeps icons (and accessible names); the drawer is for genuinely small screens.
  8. Document surfaces use .masthead, not .appbar — no sticky, no border.
