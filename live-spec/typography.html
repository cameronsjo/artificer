Two families, two surfaces. JetBrains Mono for tools — terminals, dashboards, configuration. iA Writer Quattro for documents — READMEs, design specs, prose. Pick by surface kind before you pick by element.

01 The first decision — is this a tool or a document?

Body face is set by surface kind, not by element. If the page has more than ~3 paragraphs of running prose, it's a document — set body in Quattro. If it's mostly chrome around data, it's a tool — set body in JetBrains. Mixing within a project is normal.

04 Numerals — when to reach for Quattro S

Quattro's default figures are proportional — beautiful in running prose, bad in stacked columns. Quattro S keeps the outlines, fixes the widths. Always pair tabular figures with right-aligned numeric columns, and add font-variant-numeric: tabular-nums to the parent.

05 The scan hierarchy

Five levels of emphasis, in priority order. Use them deliberately — mixing levels within a paragraph is how meaning collapses.

01 · Bold anchors

A paragraph with anchor words highlighted. A reader scanning only the bolded words should still get the sentence. Bold 3–5 per paragraph — more than 5 and nothing is emphasized.

02 · Code styling

Identifiers, paths, and values render as accent-colored mono — the user's eye learns that styled tokens are things they might copy or reference, the same way terminals train that reflex.

03 · Bold + accent = actionable

Reserve bold + gold for things the user can actually click or press. Overloading this level makes clickable items invisible.

04 · Regular weight · default

Body text lives here. Plain, calm, left-aligned, capped at 50–70 characters per line. Nothing to scan for — the bolded anchors carried the weight.

05 · Secondary color · receded

Timestamps, byline, metadata, captions. Visually present but clearly demoted — the brain can skip these on first pass and come back on a second read.

07 Paragraph rules

  • Max 2–4 sentences per paragraph. Longer paragraphs collapse into walls.
  • Letter-spacing ≥ 0.01em, word-spacing ≥ 0.16em (WCAG 1.4.12).
  • Inverted pyramid. Summary first, supporting detail second. Never bury the lead.
  • Left-align only. No justified text — rivers disrupt ADHD reading.
  • Line length 50–70 characters. Shorter than typography-standard 75.
  • Paragraph spacing ≥ 2× font size. Air between blocks matters more than air inside them.
  • Headings are informative. Scanning only the headings should convey page structure.
  • Italics are fine for emphasis or citations in document prose; avoid in dense tool body where rhythm matters most.

08 Font stack fallbacks

Body face on document surfaces. If Quattro S is installed (tabular figures), it preempts the base Quattro everywhere — useful for dashboards that mix prose and stacked data.
--font-mono JetBrains Mono · Berkeley Mono · ui-monospace · SF Mono · Menlo · monospace code, identifiers, numerals; tool-surface body
Always used for code blocks, paths, and numeric IDs. Also the body face when a region is wrapped in .surface-tool — the surface swap is one class, not per-element.
