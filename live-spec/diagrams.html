Artificer · Patterns · Diagrams

diagrams.

Boxes and arrows. Diagrams should look like the system they describe — same type, same colors, same weight as everything else. Same primitives whether you draw by hand, render Mermaid, or use React Flow. The system gives you tokens and a small kit of SVG classes; you compose.

SVG primitives

Apply .dia-node / .dia-edge / .dia-edge-label classes to inline SVG and the diagram theme follows the rest of the system. Reusable arrow marker defined once at the top of the page.

1 · Flow — "what happens?"

Accent border on the node that "is the system" you're describing — the rest are context.

2 · Sequence — "in what order?"

Solid = synchronous. Dashed = async/return. Strong stroke = the message that resolves the flow.

3 · System map — "what's connected to what?"

.dia-node--accent on the center; .dia-node--ghost on planned/optional. Dashed edge = "not yet wired."

4 · Layered architecture — "what sits on what?"

Color rules

  • Default node = surface color. Nodes are part of the page; only the type and border distinguish them.
  • One accent node per diagram. The thing the diagram is about. If everything is highlighted, nothing is.
  • Ghost nodes (dashed) for "planned / optional" — distinct from solid nodes without needing a key.
  • Edge weight encodes resolution, not importance. Use the strong stroke for the message that closes a flow; everything else is the default.
  • Labels live above the edge, mono, with a stroke-painted background so they stay legible at any angle.
  • No more than 9 nodes per diagram. Beyond that, group into sub-systems and link to a zoomed view.

Mermaid theming

Mermaid in Markdown reads CSS variables when you provide a themeVariables initializer. Drop this once at app boot — every diagram inherits the system.

mermaid.initialize({
  startOnLoad: true,
  theme: 'base',
  themeVariables: {
    fontFamily:    'JetBrains Mono, monospace',
    fontSize:      '13px',
    primaryColor:        getCss('--bg-raised'),
    primaryTextColor:    getCss('--fg'),
    primaryBorderColor:  getCss('--border'),
    lineColor:           getCss('--fg-secondary'),
    secondaryColor:      getCss('--bg-inactive'),
    tertiaryColor:       getCss('--bg'),
    nodeBorder:          getCss('--border'),
    edgeLabelBackground: getCss('--bg'),
    /* accents */
    classText: getCss('--fg'),
  },
});

function getCss(v) {
  return getComputedStyle(document.documentElement).getPropertyValue(v).trim();
}

Re-init on theme toggle so cream mode picks up the right tokens. Single hard rule: don't override fontFamily per-diagram — set once globally.

Excalidraw palette

Excalidraw doesn't read CSS variables — paste these hex values into a custom palette so hand-drawn sketches match the rest of the system.

Strokes
#ffffff fg #c5c8c6 secondary #e0b558 accent #e8836f urgent
Fills
#292c33 bg #313540 raised #3c4150 overlay

Stroke style: "thin" or "bold" (not "extra-bold"). Roughness: "architect" (low) for system maps, "artist" (medium) for sketches. Avoid "cartoonist" — too noisy for the voice.

React Flow theming

For interactive diagrams (drag-to-arrange, click-through). Set CSS overrides at the wrapper level; React Flow inherits.

/* Wrap your <ReactFlow /> in a div with this class */
.rf-artificer .react-flow__node {
  background: var(--bg-raised);
  color: var(--fg);
  border: 1px solid var(--border);
  border-radius: var(--radius-sm);
  font-family: var(--font-mono);
  font-size: 12px;
  padding: 10px 14px;
}
.rf-artificer .react-flow__node.selected {
  border-color: var(--accent);
  box-shadow: 0 0 0 2px color-mix(in oklch, var(--accent) 30%, transparent);
}
.rf-artificer .react-flow__edge-path {
  stroke: var(--fg-secondary);
  stroke-width: 1.25;
}
.rf-artificer .react-flow__edge.selected .react-flow__edge-path {
  stroke: var(--accent);
}
.rf-artificer .react-flow__background {
  background: var(--bg);
}
.rf-artificer .react-flow__controls button {
  background: var(--bg-overlay);
  border-color: var(--border);
  color: var(--fg);
}

Anti-patterns

  • Rainbow boxes. Every node a different color reads as decoration, not encoding. Stick to default + one accent + ghost.
  • Drop-shadow on every node. Adds visual weight without information. Reserve for elevation in real UI, not in diagrams.
  • Sans labels in mono diagrams. Mismatch reads as a pasted screenshot. Use mono for nodes; sans is fine for swimlane headers.
  • Auto-layout that re-flows on theme change. Lock layout; only theme/colors react.
  • "Click for details" with no visible affordance. If a node is interactive, give it a hover lift or border-accent; don't make it look static.
