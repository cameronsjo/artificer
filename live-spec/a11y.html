Focus rings — already wired

Every focusable element gets a 2px --accent outline with 2px offset. Try tabbing through the page.

Then me 
/* Already in artificer.css */
button:focus-visible, input:focus-visible, select:focus-visible,
[tabindex]:focus-visible, [role="button"]:focus-visible {
  outline: 2px solid var(--accent);
  outline-offset: 2px;
}

Tab from a fresh page reload — the skip link appears in the top-left. Always include it as the first focusable element.

The audit checklist

Run through this before shipping any new view. Most items map to existing utilities; a few require thought.

One <h1> per page; headings nest in order (no h2 → h4 jumps). Helps screen-reader users navigate by landmark.
Every form input has a <label for>. Placeholder is not a label.
Errors use aria-invalid="true" + aria-describedby pointing to the error message id.
Color is not the only signal. Status badges include a dot AND text. Required fields say "required," not just a red asterisk.
All interactive elements are reachable by keyboard. No onclick on plain divs without tabindex="0" + role + Enter/Space handlers.
Interactive SVG nodes get the same contract. tabindex="0" + role="button" + aria-label + Enter/Space, with a visible :focus-visible ring. See Diagrams § Interactive nodes.
Focus order matches visual order. No CSS order tricks that put Tab out of sequence.
Modals trap focus via artificer-focus.js; Esc closes; focus returns to the trigger.
Touch targets ≥ 44 × 44 px. Buttons, toggles, links in nav. Smaller is OK in dense tables.
Images have alt — empty alt="" for decorative, descriptive otherwise. Icons that are also labels need an aria-label on the parent.
Honor prefers-reduced-motion — already wired; durations collapse to 0ms. Don't re-introduce hard-coded transitions.
Page works at 200% zoom without horizontal scroll. Use rem/em for type, min()/max() for widths.
Page is usable without JavaScript for content reading. Forms can require JS, but content shouldn't.

Testing

  1. Tab through the page. Can you reach everything? Is the order logical? Is the focus visible at all times?
  2. Turn off your mouse. Can you complete the primary task with just the keyboard?
  3. Run axe DevTools. Browser extension, free, finds 90% of issues. Aim for zero violations.
  4. VoiceOver / NVDA pass. At least once per major view. Listen to the page; if it makes sense aurally, it's good.
  5. Set prefers-reduced-motion in OS settings and reload. Nothing should jump or shimmer.
